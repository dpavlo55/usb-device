== Reference Implementation

The reference system is the https://github.com/stnolting/neorv32[NEORV32] RISC-V processor with `usb_top`
on a Digilent Arty A7-100 (Xilinx Artix-7 XC7A100T). The same system, with the FPGA replaced by a
simulated host, runs the firmware-in-the-loop tests (`tb/vhdl/usb_top_tb.vhd`).

:sectnums:
=== System Structure

.Reference system on the Arty A7-100
image::reference_system.svg[Reference system on the Arty A7-100,width=100%,align=center]

* **Clocks:** a PLL makes `clk_usb` = 48 MHz and `clk_sys` = 60 MHz from the 100 MHz board oscillator.
* **Resets:** both resets come from the PLL's `locked` and the board's RESET button, synchronized into each
  domain.
* **Bus:** NEORV32's external bus (XBUS) reaches `usb_top` through an XBUS-to-AXI4-Lite bridge. The core
  occupies `0xF0000000` to `0xF0001FFF` (8 KiB window: registers at `0xF0000000`, RAM at `0xF0001000`).
* **Interrupt:** `irq` drives NEORV32's machine external interrupt.
* **Processor:** RV32IM, 32 KiB IMEM at `0x00000000`, 16 KiB DMEM at `0x80000000`, instruction and data
  caches disabled, base counters (`Zicntr`) enabled. Firmware is loaded through NEORV32's UART bootloader.

.Board connections
[cols="<4,<3,<5"]
[options="header",grid="rows"]
|=======================
| Port                                  | Pin                | Board
| `usb_pu`, `usb_vbus`, `usb_dp`, `usb_dn` | E15, E16, D15, C15 | Pmod JB, LVCMOS33
| `uart_txd` / `uart_rxd`               | D10 / A9           | USB-UART (FTDI), 19200 8N1
| `led` (board top level)               | H5 (LD4)           | VBUS present, driven from the `usb_vbus` pin
|=======================

.Timing constraints
[NOTE]
`clk_usb` and `clk_sys` meet only in synchronizers, handshakes and the dual-port RAM. The constraints mark
the asynchronous inputs (`usb_vbus`, `usb_dp`, `usb_dn`, reset) and the outputs as false paths.

=== Resource Utilization

The whole reference system (NEORV32, bridge, `usb_top` and the board logic) after implementation on the
XC7A100T. The design meets timing with a worst negative slack of +3.0 ns.

[cols="<4,>2,>2,>2"]
[options="header",grid="rows"]
|=======================
| Resource           | Used | Available | Util.
| Slice LUTs         | 5509 | 63400     | 8.7 %
| Slice registers    | 3901 | 126800    | 3.1 %
| Block RAM tiles    | 16   | 135       | 11.9 %
|=======================

.Core-only figures
[NOTE]
These numbers include the processor. Vivado's hierarchical report (`report_utilization -hierarchical`)
gives the share of `usb_top` alone. The shared RAM uses block RAM in proportion to `RAM_ADDR_WIDTH`.

=== Throughput

Bulk CDC-ACM throughput, measured with `tools/usb_bench.py` with the `sw/app/cdc_bench` firmware: 1 MiB x 3
runs, every byte checked. The full-speed bulk ceiling is 19 packets of 64 bytes per 1 ms frame, i.e.
1.216 MB/s.

[cols="<4,^2,^3"]
[options="header",grid="rows"]
|=======================
| Mode                               | Throughput         | Share of the bus ceiling
| sink (host -> device)              | 0.94 MB/s          | 78 %
| sink, device checks every byte     | 0.94 MB/s          | 78 %
| source (device -> host)            | 1.09 MB/s          | 88 %
| echo (both directions at once)     | 0.57 MB/s each way | 94 % of the shared bus
|=======================

**Host dependence.** Bulk OUT throughput depends strongly on the host controller: one port on the test PC
capped OUT at 0.25 MB/s, while another reached 0.94 MB/s. In simulation, with a host that never backs off,
the device keeps up with the bus in both directions: no NAKs and 51 µs per 64-byte packet.

**What it takes.** The device-side features that make these numbers possible are double buffering
(<<_double_buffering>>), split IN transfers (<<_split_in_transfers>>) and the zero-copy HAL path; `sw/tests/ram_bench`
measures the CPU cycles per access to the shared RAM and registers.
