== Overview

This core is a USB 2.0 full-speed (12 Mbit/s) **device** controller written in portable VHDL-2008, with a
portable C device stack that runs on any 32-bit CPU that can reach the core's AXI4-Lite port. The PHY is
digital: D+ and D- connect to FPGA pins with a 1.5 kΩ pull-up on D+, and no external USB transceiver chip
is needed.

The hardware handles everything with bus timing: line coding, packets, CRCs, handshakes, data toggles and
the turnaround. Software sees endpoint buffers in a shared RAM and an arm/complete handshake per buffer;
it never has to answer within a bit time. The C stack on top implements the USB Chapter 9 device framework
and a CDC-ACM (virtual COM port) class.

The reference system uses the https://github.com/stnolting/neorv32[NEORV32] RISC-V soft core on a Digilent
Arty A7-100, where the core enumerates on Windows and Linux as a CDC-ACM virtual COM port.

=== Key Features

**Hardware**

* USB 2.0 full speed, device only. The core covers the digital PHY, the packet layer (NRZI, bit stuffing,
  CRC5/CRC16, PID checks) and transactions (handshakes, data toggles, STALL, turnaround).
* 16 endpoint entries. Each entry has a configurable endpoint number, direction and type (control, bulk,
  interrupt or isochronous) and a buffer of 8 to 1024 bytes.
* One shared buffer RAM, mapped directly into the CPU's address space. Its size is set by one parameter,
  `RAM_ADDR_WIDTH`, from 1 KiB to 64 KiB. Software reads the size from a register.
* Optional double buffering per endpoint: two entries work as a ping-pong pair, so the host's packets are
  ACKed back to back while software empties the other buffer.
* Split IN transfers: one arm sends up to a whole buffer as several max-size packets, with one interrupt
  per transfer.
* SETUP handling in hardware: the 8 bytes are written only after the packet has been accepted, and control
  endpoints are unstalled automatically.
* Bus states: bus reset detection, suspend after 3 ms of idle bus, resume, remote wakeup with the
  specification's timing, SOF frame number, and VBUS detection with the D+ pull-up gated by VBUS in hardware.
* AXI4-Lite register interface, generated from SystemRDL together with a C header, an HTML register
  reference and a pyuvm register model.
* Two clock domains: a 48 MHz USB clock (4x oversampling) and any system clock.
* Vendor-neutral VHDL-2008 with no primitives, attributes or IP from any FPGA vendor.

**Software**

* Plain C11 with no CPU or SoC dependency; the core's base address is passed in at run time.
* Four layers that can each be used on their own: register access, HAL, device core (Chapter 9 standard
  requests) and classes (CDC-ACM provided).
* Porting takes four functions: interrupt enable/disable and critical-section enter/exit.
* Interrupt-driven; one call, `usbd_process()`, does all USB work.
* API reference generated by Doxygen, linked from every software section of this document.

**Verification**

* About 120 cocotb unit and integration tests with Python reference models.
* 20 firmware-in-the-loop tests: the C stack running on NEORV32 against a simulated host.
* A pyuvm environment that runs the USB-IF USBCV Chapter 9 device tests against the RTL.

:sectnums:
=== Project Status

The core is functionally complete for full-speed devices and is verified in simulation (see
<<_verification>>). On hardware it enumerates and transfers data reliably on Windows 11 and on Linux (WSL2
via usbipd).

.Not yet done
[IMPORTANT]
The core has not been through USB-IF compliance testing or electrical (signal quality) testing. The
`crc_error` endpoint interrupt is defined in the register map but not implemented yet.

.Out of scope
[NOTE]
Low-speed and high-speed operation, host and OTG roles, and the link power management (LPM) extension are
not supported.

=== Performance Summary

Bulk CDC-ACM throughput on the reference system (NEORV32 at 60 MHz, no caches), measured with
`tools/usb_bench.py`, 1 MiB x 3 runs, every byte checked. <<_throughput>> has the details.

.Bulk throughput
[cols="<4,^2,^3"]
[options="header",grid="rows"]
|=======================
| Mode                               | Throughput         | Share of the 1.216 MB/s bus ceiling
| sink (host -> device)              | 0.94 MB/s          | 78 %
| sink, device checks every byte     | 0.94 MB/s          | 78 %
| source (device -> host)            | 1.09 MB/s          | 88 %
| echo (both directions at once)     | 0.57 MB/s each way | 94 % of the shared bus
|=======================

=== Building the Documentation

This data sheet is written in https://asciidoctor.org[AsciiDoc]. The software reference is generated by
https://www.doxygen.nl[Doxygen] from the comments in `sw/usb/` and `sw/port/neorv32/`, using `sw/Doxyfile`.
`docs/Makefile` builds both into `docs/public/`, side by side, so the HTML data sheet links straight into
the software reference.

[source,sh]
----
make -C docs html      # docs/public/index.html          (needs asciidoctor)
make -C docs doxygen   # docs/public/sw/index.html       (needs doxygen; graphs need Graphviz)
make -C docs pdf       # docs/public/pdf/usb_device_datasheet.pdf  (needs asciidoctor-pdf)
make -C docs all
----

.Doxygen links in the PDF
[TIP]
The HTML data sheet links to the Doxygen pages by a relative path (`sw/`). A PDF has no such neighbour:
pass the URL where the software reference is published, e.g.
`make -C docs pdf DOXYGEN_URL=https://<host>/sw`.

The register map in <<_register_map>> follows `rdl/usb_device.rdl`. `make -C rdl html` generates a
browsable register reference from the same source into `html/`.
