== Software Framework

`sw/usb/` is a USB 2.0 full-speed device stack for this core. It is plain C11 with no CPU or SoC
dependency: the CPU-specific part is one small port file, and the core's base address is passed in at run
time. This chapter gives the structure and the rules; the function-level reference is generated by Doxygen.

.Software reference (Doxygen)
[TIP]
The Doxygen reference documents every public type and function, with call and caller graphs:

link:{dox-annotated}[data structures]. Build it with `make -C docs doxygen` (or
`make -C sw docs`, which writes `sw/build/doxygen/html/`).

=== Configuration

All options have defaults in `usb_config_default.h`. An application overrides them in its own
`usb_config.h` on the include path; it is picked up automatically when the compiler supports
`+__has_include+`, otherwise define the values on the command line.

[cols="<4,^2,<8"]
[options="header",grid="rows"]
|=======================
| Option                     | Default | Meaning
| `USB_CONFIG_CHECK_PARAMS`  | `1`     | check API parameters and return `USB_ERR_PARAM` on misuse; `0` removes the checks
| `USB_EP0_SIZE`             | `64`    | maximum packet size of EP0: 8, 16, 32 or 64
| `USBD_MAX_CLASSES`         | `4`     | class drivers per device
| `USBD_MAX_INTERFACES`      | `8`     | interfaces of the largest configuration
| `USBD_CTRL_BUFFER_SIZE`    | `256`   | control transfer buffer; longer OUT data stages are refused with STALL
| `USBD_CDC_ACM_RX_SIZE`     | `256`   | CDC-ACM receive ring, bytes
| `USBD_CDC_ACM_TX_SIZE`     | `256`   | CDC-ACM transmit ring, bytes
| `USBD_CDC_ACM_BUFFERS`     | `2`     | buffers per CDC-ACM bulk endpoint (2: double buffering)
| `USBD_CDC_ACM_IN_TRANSFER` | `256`   | bytes per IN arm (split transfer); power of two, at most 1024 and the TX ring
| `USB_PROFILE(point)`       | empty   | profiling hook on the packet path, points 1 to 7
| `USB_ASSERT(condition)`    | empty   | called on internal inconsistencies
|=======================

All functions return `usb_status_t`: `USB_OK`, `USB_ERR_PARAM`, `USB_ERR_BUSY` (a transfer is in progress),
`USB_ERR_NO_RESOURCE` (no free entry, buffer RAM or table slot) or `USB_ERR_STATE` (not allowed now, e.g.
the endpoint is not open).

:sectnums:
=== Porting

[cols="<3,<4,<4"]
[grid="none"]
|=======================
| Software files: | `usb_port.h` | link:{dox-usb-port}[Software reference (Doxygen)]
|                 | `port/neorv32/usb_port_neorv32.c` | link:{dox-port-neorv32-c}[Software reference (Doxygen)]
|=======================

The library contains no platform code. A port implements four functions for the target CPU:

[cols="<5,<8"]
[options="header",grid="rows"]
|=======================
| Function                                      | Does
| `void usb_port_irq_enable(void)`              | unmask the core's `irq` at the interrupt controller
| `void usb_port_irq_disable(void)`             | mask it
| `uint32_t usb_port_enter_critical(void)`      | keep `usbd_process()` from running (e.g. mask the USB interrupt); return the state to restore
| `void usb_port_exit_critical(uint32_t state)` | undo the matching enter
|=======================

Then pass the core's base address to `usbd_init()` (or `usb_hal_init()`), and call `usbd_process()` from
the handler of `irq`, or from the main loop.

**NEORV32 port.** `irq` is the machine external interrupt. `usb_port_neorv32_fast_irq(handler)` installs a
trap handler that calls `handler` for it and `usb_port_neorv32_other_trap(mcause)` for every other trap.

:sectnums:
=== Execution Model

All USB work happens in **`usbd_process()`**. It reads the pending events of the core, runs the HAL, the
device core and the class callbacks, and re-arms buffers.

* Call it from the USB interrupt handler (recommended) or from a main loop, but always from **one**
  context.
* Class and application callbacks run inside it. Keep them short; do slow work, such as UART output, in the
  main loop.
* Class API functions called from the main loop (`usbd_cdc_acm_read()`, `usbd_cdc_acm_write()`) protect
  themselves with the port's critical section.

**VBUS.** `usbd_connect(dev, true)` only requests the attach. Hardware drives the pull-up while VBUS is
present, and `usbd_process()` follows `bus_event.vbus`: it attaches when VBUS appears; on VBUS loss it
releases the pull-up, closes the configuration and returns to `USBD_STATE_DETACHED` with address 0. The
application does not poll VBUS. A bus reset seen while detached does not change the state.

**Suspend and remote wakeup.** L3 keeps the device state, address and configuration across a suspend,
exposes `usbd_suspended()` and calls `usbd_app_t.suspend_changed`. `usbd_remote_wakeup()` wakes the host,
only while suspended and while the host has enabled remote wakeup.

**Device states.** `usbd_state()` returns `USBD_STATE_DETACHED`, `USBD_STATE_DEFAULT`, `USBD_STATE_ADDRESS`
or `USBD_STATE_CONFIGURED` (USB 2.0 section 9.1.1); suspend is orthogonal to these.

:sectnums:
=== Hardware Abstraction Layer (L2)

[cols="<3,<4,<4"]
[grid="none"]
|=======================
| Software files: | `usb_hal.h`, `usb_hal.c` | link:{dox-usb-hal}[Software reference (Doxygen)]
|=======================

The HAL hides entries and RAM addresses behind USB endpoint addresses (`0x01` OUT, `0x81` IN, ...). It
allocates entries and buffers within the RAM size the core reports, and turns the core's interrupts into
events delivered to one callback.

.HAL events
[cols="<4,<8"]
[options="header",grid="rows"]
|=======================
| Event                      | Meaning
| `USB_HAL_EVENT_BUS_RESET`  | bus reset: address 0, every endpoint except EP0 closed
| `USB_HAL_EVENT_SETUP`      | a SETUP packet on EP0 (8 bytes in the event); any EP0 transfer was aborted
| `USB_HAL_EVENT_XFER_DONE`  | a transfer finished
| `USB_HAL_EVENT_SUSPEND`    | the bus has been idle for 3 ms
| `USB_HAL_EVENT_RESUME`     | bus activity ended a suspend
| `USB_HAL_EVENT_VBUS`       | VBUS appeared or went away; `usb_hal_vbus_present()` has the level
|=======================

.Main HAL functions
[cols="<5,<8"]
[options="header",grid="rows"]
|=======================
| Function | Does
| `usb_hal_init()`                 | take over the core at a base address, register the event callback
| `usb_hal_connect()`              | request or release the pull-up
| `usb_hal_ep_open()`              | open an endpoint with one buffer
| `usb_hal_ep_open_double()`       | open a double-buffered endpoint (two entries, two buffers)
| `usb_hal_ep_open_ex()`           | open with 1 or 2 buffers of a given transfer size; IN uses split transfers
| `usb_hal_ep_xfer()`              | start a copy-based transfer of any length, with optional ZLP
| `usb_hal_ep_buffer()`, `usb_hal_ep_arm_raw()`, `usb_hal_ep_done_buffer()` | zero-copy path: fill or read the buffer in the shared RAM directly
| `usb_hal_ep_stall()`, `usb_hal_ep0_stall()` | halt an endpoint; resuming also resets its toggle
| `usb_hal_set_address()`, `usb_hal_remote_wakeup()` | device address, remote wakeup
| `usb_hal_process()`              | handle every pending event of the core
|=======================

.Copy or zero copy
[TIP]
`usb_hal_ep_xfer()` copies between a RAM buffer of the application and the shared RAM, packet by packet.
For throughput, use the zero-copy path: write IN data straight into `usb_hal_ep_buffer()` and arm it with
`usb_hal_ep_arm_raw()`, or read OUT data from `usb_hal_ep_done_buffer()` in the completion callback. Do not
mix the two on one endpoint.

:sectnums:
=== Device Core (L3)

[cols="<3,<4,<4"]
[grid="none"]
|=======================
| Software files: | `usbd.h`       | link:{dox-usbd}[Software reference (Doxygen)]
|                 | `usbd_core.c`, `usbd_ctrl.c`, `usbd_std.c` |
|=======================

The device core implements the USB 2.0 Chapter 9 device framework:

* **Control transfers on EP0:** SETUP, data and status stages. The status OUT of a control read is armed
  together with the data stage, so a host that ends the read early is handled. `SET_ADDRESS` takes effect
  after its status stage.
* **Standard requests:** `GET_DESCRIPTOR` (device, configuration, string; ASCII strings are sent as UTF-16),
  `SET_ADDRESS`, `SET_CONFIGURATION`, `GET_CONFIGURATION`, `GET_STATUS`, `SET_FEATURE`/`CLEAR_FEATURE`
  (`ENDPOINT_HALT`, `DEVICE_REMOTE_WAKEUP`), `SET_INTERFACE`, `GET_INTERFACE`.
* **Descriptors:** the application provides them in read-only memory through `usbd_descriptors_t`: the
  device descriptor, the configuration descriptors, ASCII strings and the language ID.
* **Request routing:** interface and endpoint requests go to the class driver that owns them; vendor
  requests to the device go to `usbd_app_t.vendor_request`.

.Minimal application
[source,c]
----
static usbd_t usb;
static usbd_cdc_acm_t cdc;

static void usb_irq_handler(void) { usbd_process(&usb); }

int main(void)
{
    usbd_cdc_acm_init(&cdc, NULL);
    usbd_init(&usb, USB_DEVICE_BASE, &app_descriptors, NULL);
    usbd_register_class(&usb, &usbd_cdc_acm_class, &cdc);

    usb_port_neorv32_fast_irq(usb_irq_handler);   /* port-specific */
    usb_port_irq_enable();
    usbd_connect(&usb, true);

    uint8_t buffer[64];
    for (;;) {
        const uint32_t n = usbd_cdc_acm_read(&cdc, buffer, sizeof buffer);
        for (uint32_t sent = 0; sent < n;) {
            sent += usbd_cdc_acm_write(&cdc, &buffer[sent], n - sent);
        }
    }
}
----

`sw/app/cdc_echo/` is the complete version of this example, with its descriptors.

:sectnums:
=== Class Drivers (L4)

[cols="<3,<4,<4"]
[grid="none"]
|=======================
| Software files: | `usbd_class.h`     | link:{dox-usbd-class}[Software reference (Doxygen)]
|=======================

A device registers up to `USBD_MAX_CLASSES` drivers with `usbd_register_class()`. On `SET_CONFIGURATION`,
L3 offers each function (an interface association, or an interface at alternate setting 0) to the
registered drivers. A new class implements `usbd_class_t`:

[cols="<3,<9"]
[options="header",grid="rows"]
|=======================
| Member      | Called
| `reset`     | on bus reset or deconfiguration: forget the configuration (endpoints are closed already)
| `open`      | with the descriptors from an interface on: claim the interfaces, open their endpoints with `usbd_ep_open()`, return the bytes consumed (0 to decline); also on `SET_INTERFACE`
| `control`   | for class or vendor requests to its interfaces or endpoints: answer with `usbd_ctrl_send()`, ask for data with `usbd_ctrl_receive()`, return `false` to STALL
| `xfer_done` | when a transfer on one of its endpoints finished
|=======================

:sectnums:
=== CDC-ACM Class

[cols="<3,<4,<4"]
[grid="none"]
|=======================
| Software files: | `usbd_cdc_acm.h`   | link:{dox-usbd-cdc-acm-h}[Software reference (Doxygen)]
|                 | `usbd_cdc_acm.c`   | link:{dox-usbd-cdc-acm-c}[Software reference (Doxygen)]
|=======================

A virtual COM port (USB CDC, Abstract Control Model): one notification interrupt IN endpoint and a bulk OUT
and IN pair. Operating systems bind their standard serial driver to it, so it needs no driver on the host.
`USBD_CDC_ACM_DESCRIPTOR()` expands to its interface association, interfaces and endpoints for a
configuration descriptor.

* **Data path:** RX and TX rings in RAM. `usbd_cdc_acm_read()` and `usbd_cdc_acm_write()` take and queue
  bytes from thread context; `usbd_cdc_acm_available()` and `usbd_cdc_acm_write_space()` report the fill.
  The bulk endpoints are double-buffered and IN uses split transfers of `USBD_CDC_ACM_IN_TRANSFER` bytes.
* **Line state:** `usbd_cdc_acm_connected()` is true while configured and the host holds DTR (a terminal has
  the port open). `usbd_cdc_acm_line_coding()` returns the baud rate and format the host set (115200 8N1
  until then); the class only stores them, since there is no physical line.
* **Callbacks** (all optional, run in `usbd_process()`): `received`, `line_state_changed`,
  `line_coding_changed`.

=== Building

`sw/Makefile` builds the firmware for NEORV32. It reuses NEORV32's startup code, libraries, linker script
and image generator, compiles the stack with `-O2` and links it into every program. The register header is
generated from the RDL as part of the build.

[source,sh]
----
make -C sw image                                   # firmware + IMEM image for simulation
python tools/cocotb_runner.py --sw-test cdc_echo   # build and run a program against a simulated host
make -C sw docs                                    # Doxygen reference into sw/build/doxygen/html
----

Toolchain: GNU Make, the xPack `riscv-none-elf-gcc` (set `RISCV_PREFIX` for another prefix), a native `gcc`
for the image generator, and Python with PeakRDL. `sw/README.md` has the details of the firmware builds and
tests.
